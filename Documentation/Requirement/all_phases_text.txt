PIE – Platform Intelligence Engine

Phase 1 – Product Definition & Vision

Document Version: 1.0Project Status: CompleteOwner: PIE Engineering Team

1. Executive Summary

Platform Intelligence Engine (PIE) is an AI-powered engineering platform designed to help engineers understand Azure Data Factory environments before making changes.

Rather than functioning as a documentation generator, PIE continuously transforms Azure Data Factory metadata into actionable engineering intelligence.

PIE combines Azure Data Factory Management APIs, Knowledge Graphs, Azure AI Search, and Azure AI Foundry to provide a unified platform for discovery, explanation, dependency analysis, impact assessment, and engineering decision support.

The first release focuses exclusively on Azure Data Factory to validate the concept and establish a strong architectural foundation for future expansion.

2. Background

Modern Azure Data Factory environments often contain hundreds of pipelines, datasets, linked services, triggers, and activities.

As these environments grow, engineering knowledge becomes fragmented.

Typical challenges include:

Lack of reliable documentation

Engineers leaving the organization

Long onboarding cycles

Manual dependency analysis

Difficulty understanding pipeline behavior

High risk during production changes

Although Azure Data Factory stores extensive metadata, it is optimized for execution rather than engineering understanding.

PIE aims to bridge this gap.

3. Vision Statement

Help data engineers understand Azure Data Factory before making changes.

PIE is intended to become the engineering knowledge layer that sits on top of Azure Data Factory.

Its objective is to transform technical metadata into engineering intelligence.

4. Mission

Transform Azure Data Factory metadata into actionable engineering intelligence using Azure-native AI services.

5. Product Philosophy

PIE is not:

A chatbot

A documentation generator

A replacement for Azure Data Factory Studio

A pipeline execution platform

PIE is:

An engineering intelligence platform

A platform discovery engine

A dependency analysis engine

An AI-assisted engineering advisor

A knowledge preservation platform

6. Problem Statement

Organizations invest significant effort in building Azure Data Factory solutions.

However, understanding these solutions becomes increasingly difficult over time.

Common pain points include:

Knowledge Loss

Critical platform knowledge often resides with a small number of engineers.

Poor Documentation

Documentation becomes outdated shortly after implementation.

Manual Dependency Analysis

Engineers manually inspect multiple pipelines before making changes.

Slow Onboarding

New engineers require days or weeks before understanding the platform.

Change Risk

Deleting or modifying datasets, linked services, or pipelines may unintentionally impact downstream systems.

7. Proposed Solution

PIE continuously discovers Azure Data Factory metadata and transforms it into structured engineering knowledge.

This knowledge is organized into a Knowledge Graph, indexed using Azure AI Search, and interpreted by Azure AI Foundry to provide contextual engineering insights.

8. Project Objectives

The MVP aims to:

Connect securely to Azure Data Factory.

Discover platform assets automatically.

Build an internal dependency graph.

Generate business and technical explanations.

Enable natural language exploration.

Support engineering impact analysis.

Improve engineering productivity.

Reduce platform onboarding time.

13. Engineering Principles

PIE follows the following principles:

Metadata First

Metadata is the source of truth.

Knowledge Graph Centric

The Knowledge Graph is the core intelligence layer.

AI for Reasoning

AI interprets engineering context rather than storing platform knowledge.

Read-Only Architecture

PIE never modifies Azure Data Factory resources.

Least Privilege

Reader access is sufficient for platform discovery.

Modular Design

Each platform integration is implemented independently.

Azure Native

The solution leverages Azure-native services wherever possible.

5. Engineering Intelligence Model

PIE answers two categories of engineering questions.

Type 1 – Deterministic Questions

The requested asset is already known.

Examples:

Explain Customer_Load.

Show dependencies of Pipeline A.

Describe Dataset X.

Explain Linked Service Y.

The Context Builder retrieves metadata directly from the Knowledge Graph.

Azure AI Search is not required.

Type 2 – Discovery Questions

The requested asset is unknown.

Examples:

Which pipelines use SAP?

Which datasets contain customer information?

Show disabled triggers.

Which pipelines execute every night?

Azure AI Search retrieves relevant assets before the Context Builder prepares the prompt.
